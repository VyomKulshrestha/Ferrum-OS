## How it was read

  in `tw1_catalogue_readings/`.
- The catalogue has 56 rows in 26 families (a family is one project; a project with several adaptive
  parts has several rows).
- I re-read the update statement and the alarm decision of 42 rows at the cited lines and commits. Those
  rows are marked "verified". The other 14 are marked "agent only" and do not count below.
- A fifth subagent searched for prior art and re-verified the citations of the earlier triage

## What the reading found

1. **Learning from flagged samples is the norm.** 17 of the 26 families update the quantity that decides
   an alarm with samples they flagged, on the default or quickstart path. Eight of them are products or
   plugins: OpenSearch Anomaly Detection, Elastic ML, Netdata, Zabbix, Graphite, Checkmk, Grafana's
   PromQL rule pack and Skyline.
2. **Holding flagged samples out is rare and partial.**
   - The SPOT authors' code, libspot and PySAD's SPOT calibrator leave alarms out of the tail fit, as
     the SPOT paper does. StreamAD's SPOT detector does not: any value above its initial threshold
     refits the peaks.
   - river's `protect_anomaly_detector` shields the wrapped model. The running quantile of
     `QuantileFilter` still takes every score.
   - Elastic ML down-weights improbable samples to a floor of 0.01 and never to zero, and its score
     normaliser takes every score.
3. **Several defaults report only the start of a sustained anomaly while the model keeps learning from
   it.** Random Cut Forest, as OpenSearch configures it, sets the grade to zero inside a run (drift
   correction and alert-once). The Numenta likelihood reports consecutive red points after the first at
   the yellow level. Netdata needs every one of its models to agree, so the newest model can clear a
   point once it has trained on the anomaly, and its documentation says a new anomaly is learned as
   normal within 3 hours.
4. **What is on by default differs.** Netdata's ML runs by default. OpenSearch and Elastic apply the
   defaults read here once a detector or job is created. The Zabbix, RRDtool, Graphite and Checkmk
   functions are opt-in.
5. **In some targets the model adapts under a fixed threshold**: Merlion's quickstart detector, the
   online Mahalanobis detector of alibi-detect, the Random Cut Forest itself.
6. **The catalogue can return "does not adapt".** PyOD, Darts, alibi-detect's fitted thresholds,
   Merlion's post-rules, Kitsune after its grace period and river's `ThresholdFilter` are static.
7. **Set aside, not counted.** Orion, Luminol and Yahoo EGADS compute a threshold from the batch they
   score, so there is no run-time threshold for a campaign to move. ADTK's `PersistAD` compares with a
   rolling window by design, to stop flagging a sustained shift.

## Prior art

The search found no published test of any listed target for absorption or poisoning, so the prior-art
clause of the plan does not apply. The closest work is Rubinstein et al., ANTIDOTE (IMC 2009), on the
authors' own PCA detector. Vendor documentation admits the effect (Netdata, Azure Monitor, Datadog,
CloudWatch, Elastic) or ships a guard against it (river, Elastic, CloudWatch, Splunk ITSI); no source
measures whether a guard holds against an attacker.

## Consequences for the design of paper 2

- **Two input levels.** Some targets threshold a score that another model produces (river's filters,
  PySAD's and StreamAD's calibrators, the Numenta likelihood, Telemanom, SPOT). They can take the tt1
  monitor score, and the tt1 score-level campaigns apply unchanged. The others model a raw signal
  (Random Cut Forest, OpenSearch, Netdata, Zabbix, RRDtool, Graphite, the PromQL rules, Merlion,
  alibi-detect). For those the campaigns must be written at the sensor level, as in the tt1f process
  campaigns.
- **Alert-once defaults change what "detected" means.** Any-alarm and onset counts must both be
  reported, as in tt1, and the test after a campaign must be a new event, not the continuation of a run.
- **Guards are a test object of their own.** Each shipped guard (river's protection switch, Elastic's
  skip rules, SPOT's alarm branch) gets the campaign that tt1 predicts will pass it.
- **Elastic ML** is read but not run until its licence terms for a trial deployment and for publishing
  measurements are read.
- **Docker** is installed on the development machine and was not running on 2026-11-11. OpenSearch,
  Netdata and Zabbix need it.

## Observations that maintainers may want (not attack results)

Unverified unless marked. Reporting any of them upstream is the author's decision.

- river `ThresholdFilter`: with `protect_anomaly_detector=False` the base-class condition
  `if self.protect_anomaly_detector and not self.classify(...)` never updates the wrapped detector
  (condition read by me at `river/base/anomaly_detector.py:155`; intent not confirmed).
- Random Cut Forest: the Rust port's thresholder is reported to learn gaps above the mean where the
  Java code learns gaps below it (agent only).
- Netdata: the documentation describes the threshold as a percentile of the training data; the code
  scales the distance by the range between the smallest and largest training distance
  (`src/ml/ml_kmeans.cc:116-123`, read by me).
- Luminol: the README calls `score_percent_threshold` a percentile; the code multiplies the largest
  score by it (`src/luminol/anomaly_detector.py:115`, read by me).
- StreamAD: the `SpotDetector` docstring gives a default `window_len` of 200, the code 50 (agent only).
- MLPrimitives: the copy of `_find_threshold` is reported to lack the `best_cost = cost` line that
  Orion's has (agent only).

## Reference code against the tt1 re-implementations (agent only)

The group C reading compared the SPOT, DSPOT and Telemanom reference code with the rules written for
tt1. It found no difference in which samples the SPOT rules learn from. Differences that can change when
a rule alarms: the reference SPOT refits by Grimshaw's method on every peak and recomputes its threshold
only then, where `spot_gr` refits on a schedule and recomputes on every sample; the reference Telemanom
thresholds smoothed errors, judges each batch inside its own window, widens and prunes flagged
sequences, and also detects drops. These belong in the limitations of the tt1 paper if its rules are
described as "the published method"; they are listed in full in `tw1_catalogue_readings/group_C.md`.

- Families read: 26.
- Absorbing on the default path, verified: 17 (AWS Random Cut Forest, Checkmk, Elastic ML, Grafana promql-anomaly-detection, Graphite, Merlion, Netdata, Numenta anomaly likelihood, OpenSearch Anomaly Detection, PySAD, RRDtool, Skyline, StreamAD, Telemanom, Zabbix, alibi-detect, river).
- Of these, absorbing at full weight (not only down-weighted): 17 (AWS Random Cut Forest, Checkmk, Elastic ML, Grafana promql-anomaly-detection, Graphite, Merlion, Netdata, Numenta anomaly likelihood, OpenSearch Anomaly Detection, PySAD, RRDtool, Skyline, StreamAD, Telemanom, Zabbix, alibi-detect, river).
- Products or plugins among them: 8 (Checkmk, Elastic ML, Grafana promql-anomaly-detection, Graphite, Netdata, OpenSearch Anomaly Detection, Skyline, Zabbix).
- Runnable on this laptop: 14 (AWS Random Cut Forest, Grafana promql-anomaly-detection, Graphite, Merlion, Netdata, Numenta anomaly likelihood, OpenSearch Anomaly Detection, PySAD, RRDtool, StreamAD, Telemanom, Zabbix, alibi-detect, river).
- Absorbing but set aside and not counted (batch-only thresholds, change detectors by design): ADTK, Luminol, Orion, Yahoo EGADS.
- Rule (go: >= 5 absorbing families, >= 2 of them products or plugins, >= 3 runnable here; shrink: <= 2; otherwise between): **go**.
